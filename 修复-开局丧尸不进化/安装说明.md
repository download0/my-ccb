# 安装说明 — 开局远离灾变时，第一只丧尸不进化（mapgen 怪物缺少"进化追赶"）

> 类型：**C++ 源码补丁**，必须重新编译游戏，只改 JSON 不生效。
> 生成日期：2026-10-18
> 目标版本：本机 `2026-10-01-2329` / commit `69b23e8`（源码基线：上游 CDDA master `221c786e7d`）
> 上游 0.I（2026 dev）及之后的所有版本都有此问题，本补丁对同结构版本通用。

## 1. 问题

开局把灾变日期设在很多年以前时，第一次遇到的丧尸是最普通的 `mon_zombie`，
战利品也是普通丧尸的物品组；**走远再回来（泡泡重新加载）**才会变成进化形态。

## 2. 原因（一句话）

进化只在 `monster::on_load()` 里执行；地图生成放怪走的是
`map::add_spawn()` → `submap->spawns` → `map::spawn_monsters_submap()` →
`g->place_critter_at_or_within()`，**这条路径不调用 `on_load()`**（0.G/0.H 会调用，
0.I 刷怪重做时丢失）。所以新生成的怪 `upgrade_time` 一直是 `-1`，直到被卸载重载。

## 3. 改动内容

- 文件：`src/map.cpp`
- 函数：`map::spawn_monsters_submap()`
- 在 69b23e8 中的位置：第 11476–11478 行（`for( int j = 0; j < i.count; j++ )` 循环内）
- 行为：把新怪摆进泡泡后，**立刻做一次 `try_upgrade( false )`**，即按世界时间"追赶"进化；
  `i.mission_id > 0`（任务目标怪）跳过，避免任务要求的怪物类型被换掉。
- 不改：JSON、存档格式、其他刷怪路径（overmap 兽群、Lua spawn、召唤等）、`upgrade_time` 语义。
- 效果：**"第一次遇到" 与 "离开再回来" 结果一致**（形态 + `death_drops` 战利品）。

为什么是 `try_upgrade( false )` 而不是 `on_load()`：
`on_load()` 还会跑回血/速度/攻击冷却/繁殖的追赶，并触发 Lua 的 `on_creature_loaded`
回调；本补丁只需要"进化追赶"这一件事，保持 mapgen 阶段无额外副作用。

## 4. 安装（三选一）

### 方式 1：git apply（推荐，源码是 git 仓库时）

在源码仓库根目录（能看到 `src/` 的那一层）执行：

```sh
git apply --check "修复-开局丧尸不进化/升级补丁-map.cpp.patch"   # 只检查，不写入
git apply         "修复-开局丧尸不进化/升级补丁-map.cpp.patch"
```

`--check` 无输出 = 可以干净应用。

### 方式 2：手动编辑（10 秒）

打开 `src/map.cpp`，搜索 `spawn_monsters_submap`，把：

```cpp
            // This can fail, but there isn't much we can do about it if it does. We could output some
            // kind of info message, but, again, it's unlikely to result in anything that can be acted on.
            g->place_critter_at_or_within( make_shared_fast<monster>( tmp ), this, center, points );
```

替换为：

```cpp
            // This can fail, but there isn't much we can do about it if it does. We could output some
            // kind of info message, but, again, it's unlikely to result in anything that can be acted on.
            monster *const placed =
                g->place_critter_at_or_within( make_shared_fast<monster>( tmp ), this, center, points );
            // CCB: mapgen spawns must catch up with world time, as 0.G/0.H did by calling on_load()
            // right here. The 0.I spawn-placement rework dropped that call, so in a world started
            // long after the Cataclysm freshly generated monsters stayed unevolved until the
            // reality bubble reloaded them. Only run the evolution catch-up (not the whole
            // on_load()) and leave mission targets alone so MGOAL_KILL_MONSTERS still sees its
            // original target type.
            if( placed != nullptr && i.mission_id <= 0 ) {
                placed->try_upgrade( false );
            }
```

### 方式 3：整文件替换（源码版本必须完全一致）

1. 备份：`src/map.cpp` → `src/map.cpp.bak`
2. 先核对原文件 SHA256 是否为 `5DDD089B4E8F31F6BF8A2FB2F6B4C518422F7CECAAC231BF18FCD9ACE861CC6F`
   （`certutil -hashfile src\map.cpp SHA256`）；不一致说明源码版本不同，改用方式 1/2。
3. 用本目录的 `map.cpp` 覆盖 `src/map.cpp`。

## 8. 副作用与注意事项

- **任务目标怪不进化**（`mission_id > 0` 跳过）。这是对 0.H 行为的一处有意收紧：
  避免"杀掉地下室那只 `mon_zombie`"一类任务因为目标变成其他丧尸而失效。
- 进化是**一次性补算**：连续 `poly()` 到世界时间对应的形态。每一级 `poly()` 都会把
  上一形态的 `generate_inventory()` 掉落塞进 `inv`（`monster.cpp:413-418`），所以尸体会
  带多级物品 —— 这与"离开再回来"完全一致，是原版既有行为，不是本补丁引入。
- **大地图生成耗时**：灾变后数十年开局时，每只怪要连续 `poly` 十几次，进入新区域会稍慢；
  正常年份开局无影响（首次 `try_upgrade` 直接 return）。
- **Lua 平台**：不触发 `on_creature_loaded` / `on_monster_loaded`；
  `on_monster_spawn` 仍在 `place_critter_at_or_within()` 内部照常触发（observer，看到的
  是进化前的类型）。
- **上游以后修复时**：若上游在这条路径恢复了 `on_load()`，本补丁变成重复调用。
  `try_upgrade()` 第二次进来时 `upgrade_time >= 0`，不会重复进化，可以安全保留或删掉。
- 只改核心 C++：与所有模组兼容，存档兼容。
